# 自然语言条件选股技术设计

版本 v4；依据 PRD 和 `RESEARCH_REVIEW.md` 的 R1–R11 审查决议。用户已授权修订后直接实施。这里描述目标实现，实际完成状态由测试记录证明。

## 1. 最小可信链路

自然语言 → 受限解释草稿 → 结构及语义边界校验 → 用户确认 → 版本化条件 → 带来源的数据快照 → 纯函数筛选 → 逐项证据／修改差异 → 保存研究。

不运行模型生成的 SQL 或脚本，不由模型填充证券数值，不用模型自评分决定是否执行。新建／修改模式由用户界面确定；每次解释最多一次模型调用，没有自主循环重试或工具探索。

## 2. 指标字典和语义落地

FIELDS 是字段、单位、计算口径、适用性、朴素解释和不能推出的结论的共同来源。执行引擎、提示和 UI 使用同一版本，避免 UI 说的是静态 PE 而引擎用 TTM。

可执行字段仍是 revenue、profit、pe、volatility、drawdown。revenue／profit 是固定报告期累计同比百分数；不是绝对利润、扣非利润、单季度环比、增长加速或百分点变化。pe 仅正 PE(TTM)。风险窗口固定 60 个收益／61 个价格，不擅自把用户的 20 日要求改成 60 日。

每项原话映射保存 sourceText、关联条件、是否需要确认；解释的金融边界从字段字典生成。未知指标、错时间窗口、错估值口径进入 unsupported。原话片段必须能在输入中找到，但片段存在只是结构检查，不是完整语义等价证明。

## 3. 解释与修改接口

POST `/api/interpret` 输入 `query, report, conditions, mode, baseRevision`。mode 为 new 或 modify；首次请求可默认 new 以兼容原型。modify 必须包含当前条件和版本。page 只发送最近一次草稿的必要状态，不发送持仓或原始金融响应。

新建输出 conditions。修改输出受限 `operations`，只允许：

- `{type:'update', id, op?, value?}`：修改目标条件的比较符或阈值。
- `{type:'remove', id}`：删除明确指定条件。
- `{type:'add', condition}`：添加白名单条件。

更换指标采用明确 remove＋add，必须在变更对照中可见。禁止通用 JSON 路径、脚本和隐式全量覆盖。当前条件有互斥区间仍允许解析修复。无法唯一指认目标（如有两个 PE 上限）则澄清。对模型所指的目标，再用输入中的明确指标／阈值约束核对；复杂指代无法确认时交给用户，不声称补丁本身保证语义正确。

服务端应用合法补丁，返回候选 conditions、operations、baseRevision、questions、unsupported、mappings、requestedReport、实际 model 和 requestId。前端只应用当前请求、当前 baseRevision 的响应；任何过期响应丢弃。用户确认前不改变已执行 ResearchRun。

同一句“或”可能是逻辑 OR，也可能是“波动率或回撤哪个更适合”的解释选择。规则不应只凭一个字就全部拒绝；逻辑 OR 保留为未支持，解释选择进入澄清。利润未明确归母／扣非等口径时，将拟选的归母口径列为假设；不能当作用户已明确指定。

## 4. 六道执行检查

1. 输入：长度、模式、当前条件结构与版本合法。
2. 结构：模型 JSON、字段、操作符、有限数值、补丁目标合法；拒绝对象原型继承键。
3. 语义边界：显式阈值／否定范围／时间／单位／未支持要求未静默改变。无法确认就澄清。
4. 金融适用性：指标定义、报告期、窗口、正 PE、同比基期和完整价格序列正确。
5. 用户确认：重要假设已确认，未支持项已由用户明确处理；条件无矛盾且非空。
6. 数据执行：快照与策略报告期一致；异常逐项保留；同一条件与数据产生相同结果。

执行检查是软件约束，不是金融收益保证。条件冲突检查与模型结构校验分开，避免阻断用户修复冲突。

## 5. 澄清策略

必要澄清：存在会改变字段、比较对象、阈值、逻辑或时间的歧义；明显没有足够信息执行；模型违反显式要求。无需澄清：用户已经明确支持范围内的字段、运算符、阈值和所需时间。

不显示“AI 置信度 95%”。显示具体原因，例如“‘稳定’可指价格起伏或从高点跌落，请选择”。一屏最多展示本次相关的三组解释，不增加风险偏好调查和画像问卷。

## 6. 数据与证据

独立记录 reportPeriod、publishedAt、sourceTime、retrievedAt、快照构建起止。请求 traceId 与 raw 字段足以追查本次响应；它不意味着供应商保存了可任意复取的历史版本。

财报必须核对年度、累计期间、币种、归母字段和披露有效性。证据保留本期与基期原值。同比基期非正为不适用；未查现金流不等于现金流异常。价格完整性按预期交易日集合核对，拒绝重复日期、非正价格和无成交记录。年化仅是固定 √252 尺度换算，不是收益预测。

Dataset 含完整证券池，即使部分工具失败。Metric 包含 value、unit、quality、issue、evidence。任何确定失败使该股 fail；没有失败但有未知则 unknown；全部通过才 pass。不以舍入值判定边界。

同一 snapshotId 下只改条件才给出条件影响；新快照不混入比较。预览去掉一项条件是集合重算，不能解释为股价未来影响。保存时只保存已执行策略、原意、确认／省略记录、快照、结果与模型标识。

## 7. 模型与可用性

OpenRouter 请求使用 JSON Schema，并在 provider 中要求支持所需参数；无兼容免费端点时明确失败，不悄悄放宽结构要求。服务端再次验证，记录实际返回 model，不仅记录路由别名。默认一次 45 秒超时；错误提示不回显 token 或完整上游请求。

金融数据单次构建限并发 2、请求超时 12 秒、限流有界重试；缓存 900 秒、刷新间隔 60 秒。输入最长 400 字，API 有实例级频率限制；不将其宣传为全局限流或生产级抗滥用。公开演示不做后台主动轮询模型或持续抓取。

## 8. 评测与可观测性

三层验证：

| 层 | 预先定义的判定 | 不能冒充 |
|---|---|---|
| 语义 | 字段／方向／单位／时点／支持范围／未提及条件是否保留；应澄清与不应追问分别统计 | JSON 解析成功不是理解成功 |
| 执行 | 手算值、三态数量守恒、确定性、放宽集合性质、边界条件、多数据情形 | 单个快照名单相同不是条件等价 |
| 体验 | 用户能否完成确认、读懂原因、修改、比较、保存；后续真人任务复述 | 模拟用户和自动点击不是用户价值验证 |

至少 24 条设计样例；真实模型至少 6 类首轮，另对否定和局部修改各重复一次，共至少 8 次实际调用（若规则前置拦截需单独计数）。配额不足就报告未完成，不造通过率。不把同一模型同时生成的题目、答案和评分当独立真值。

记录 query／规范化期望／实际 model／requestId／promptVersion／metricDictionaryVersion／latency／结构结果／语义结果／失败分类。原始响应只留本地忽略目录，公开记录只含无隐私、无凭据的演示样例。首轮保留样例一旦被用于修复，转为回归集并如实说明，不继续称为未见测试。

## 9. 实施约束

优先补强已存在引擎、数据适配和解析；不因研究另建 RAG、训练模型、知识图谱或多代理系统。新增技术复杂度只用于保护意图、版本和证据。目标文件与验收顺序见实施计划，实际完成项见 `docs/IMPLEMENTATION.md`。

## v4 行业适用性修订

“估值合理／便宜／低估”未指定绝对倍数时，返回 unresolved=[valuation]，不生成 PE 条件。UI 要求用户自行输入绝对 PE 上限，或主动略过并留痕。绝对倍数只是用户研究约束，不是行业公允价值标准。研究框架入口解释银行、周期、成熟盈利和亏损成长企业的不同重点。iFinD 实测返回一级行业，但仅标“最新”、无明确有效日期；不据此生成行业历史分位或同业中位数筛选。
