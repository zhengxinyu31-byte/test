# 同花顺自然语言选股 PRD v5

日期：2026-10-15。状态：已实现并完成本地验证；公开发布状态见测试报告。多问法知识库见 ../../knowledge/intent-strategy-research.md；实际验收以测试记录为准。

配套：[交互与技术设计](../../designs/2026-10-15-v5-interaction-design.md) · [研究与对抗性审查](../../designs/2026-10-15-v5-research-and-review.md)。旧版 v4 文档保留为历史记录，当前交付以 v5 文档和实际验收为准。

## 1. 产品要替用户完成什么

用户说“经营改善、估值合理、走势相对稳定”，希望得到一份看得懂、能调整、值得继续核查的候选名单。系统负责选指标、定初始比较标准、取数和计算，再说明它如何理解这句话。用户主要决定研究方向、是否接受这次解释，以及下一步看哪家公司。

常规流程为：**表达想法 → 看到初筛结果及依据 → 按需调整 → 比较或保存。**

首次结果前不要求输入任何财务阈值，不要求选择公式，不设置“已理解所有口径”的必勾项。点击“按这个想法筛选”即发起一次可逆的只读筛选。系统采用的默认解释与结果同时显示，不能记作用户已经确认过的观点。

可解释性的验收标准是：用户知道为什么采用某个指标、为什么用这个标准、改动会影响什么，并且有办法核查事实。只提供术语释义或原始 JSON 不算完成。

## 2. 服务谁，在什么时刻提供帮助

目标用户：已经关注一个行业、会看行情和公司新闻，但不熟悉选股公式的中低频个人投资者。他的目标是从熟悉的公司中挑出下一步研究对象，尚未形成量化条件。这是待验证的用户假设，不附会年龄、资产规模或用户占比。

主要触发时刻：看完财报或公司点评，正在同花顺某个行业页面查看同行，产生“还有哪些类似公司符合我的想法”的需求。行业上下文已经存在，产品不重复询问市场、行业和股票池，也不要求填写风险画像问卷。

MVP 先完成白色家电同行研究场景。研究对象为“同花顺白色家电板块，剔除家电零部件板块成分”的观察组；页面简称“白电整机观察组”，规则一键可查。这是本产品定义的研究范围，不冒充申万二级行业，也不声称所有成员业务完全可比。公司业务可比性尚未逐家审核，因此只提供命名组内数值比较，不宣称是估值可比公司样本。

选择这个切口的理由：能把同一行业上下文、盈利比较、相对 PE 和历史走势连成一个具体任务；取数已找到可验证路径；可以显著减少跨行业误比。家电也受需求、出口和成本周期影响，不把它称为非周期或低风险行业。

不优先服务：没有个股研究目标的纯新手、依赖盘口的短线交易者、需要复杂回测的量化用户、寻找银行或亏损成长股专用估值的人。各类用户需要的标准不同，首版不勉强覆盖。

下一步是查看候选的差异、核查公告、保存筛选理由。成交、预测收益和买入转化不作为本任务的成功指标。

同花顺内的拟定入口是行业页面上的“按想法选股”，支持范围在入口旁说明。正式入口位置、流量与账户能力需要内部确认。本轮仍按独立 Demo 设计，默认加载明确标注的演示行业，不伪装成已经读取用户账户或自选股。

## 3. 三种交互路线的选择

| 路线 | 好处 | 主要问题 | 选择 |
|---|---|---|---|
| 指标表单预填默认值 | 改造小 | 用户仍被迫理解一排指标和参数，默认值依据容易遗漏 | 不作为主界面 |
| 逐步问答向导 | 每次问题少 | 在有结果前仍需连续选择，用户不知道答案意味着什么 | 只处理实质歧义 |
| 默认解释直接试算，结果中解释和调整 | 先提供可用结果，再让用户针对具体差异调整 | 需要防范默认锚定、误比和静默替换意图 | 采用 |

专业条件编辑保留在“查看条件”面板。能用自然语言说明的调整，不要求用户先打开编辑器。

## 4. 系统默认做哪些事

### 4.1 默认的优先顺序

1. 保留用户明确写出的指标、数值、方向、报告期和范围。
2. 后续修改保留本次已采用、但未被修改的设置。
3. 只为用户提到的模糊目标填入适用的产品默认解释。
4. 无法形成合法解释时再澄清，不猜关键缺口。

例如只输入“PE 不超过 20”，就按这条明确要求筛选，不偷偷加上利润增长和低波动；只有表达中包含相应模糊目标，才使用下面的默认解释。界面显示“按你给出的条件”，而非假称自动理解了完整投资目标。

### 4.2 默认方案的三项解释

适用条件：处于已核定的观察组，所用指标有效，且同行基准质量满足要求。估值项另有正盈利口径；走势项不以公司是否盈利决定价格数据是否有效。默认演示报告期为 **2026 年中报**，不写“最新财报”；默认价格窗口为最近 60 个已完成交易日收益、共 61 个价格。

| 用户表达 | 结果页先说什么 | 系统默认执行 | 为什么这样选 | 必须说明的局限 |
|---|---|---|---|---|
| 经营改善 | 营收、归母利润都比去年同期增加 | 同口径营收同比 > 0，归母净利润同比 > 0 | 同时看业务收入和归属于股东的利润；0 是增长与下降的分界，用户不必猜 10% 或 20% | 正增长不等于增速加快，也不能证明增长来自主营业务；本轮未核查扣非、现金流和一次性损益 |
| 估值合理 | PE 不高于本组盈利公司的中位数 | 正 PE(TTM) ≤ 合格比较组 PE 的 P50 | 先用当前同类盈利公司的中间水平缩小范围，实际倍数由数据计算 | 只比较盈利倍数，不判断公允价值；同行可能整体偏贵，增长和业务差异仍需核查 |
| 走势相对稳定 | 过去的起伏和从高点回落，都不高于本组中位数 | 60 日年化波动率 ≤ 对应 P50，且 60 日最大回撤 ≤ 对应 P50 | 同时观察日常起伏和高点后的回落，避免把持续缓跌误称为稳 | 只是历史比较，不预测后续跌幅；同行整体波动很大时，通过者也可能有较大的绝对风险 |

“归母净利润”首次出现时补一句“归属于上市公司股东的利润”。PE 的说明是“当前股价相当于每 1 元过去 12 个月每股盈利的多少倍”，不能解释成多少年保证回本。回撤用“这段时间从高点最多回落多少”解释；波动率用“日常涨跌起伏的大小”解释，并保留完整公式入口。

P50 是可调整的筛选起点，不是专家认定的合理价格、安全边界或收益最优参数。页面写“本次默认：不高于中位数”，不用“最佳参数”“AI 推荐买点”。

### 4.3 默认比较组如何产生

候选观察组 U 来自两份有版本的供应商名单做集合差，保存原名单、接口和请求标识。不能由模型临时选择几家看起来合适的公司。取数过程不能把深圳、上海同代码证券混淆；证券全代码是唯一键。

默认估值比较组 B_PE：观察组内，最近两个完整年度、所选报告期及其同比基期的归母净利润均为正且可核验的公司。2026 中报对应 2024、2025 年报及 2025、2026 中报；2025 年报对应 2024、2025 年报。该门槛用于限制默认 PE 比较的适用范围，不能据此给公司贴“优质”或“成熟”的标签。采用这项默认时，条件摘要必须同时写明“近两年及本期盈利公司的 PE 比较”，不能隐藏盈利门槛。

走势比较组 B_PRICE：观察组 U 中具有完整、有效价格窗口的公司。亏损本身不使历史波动率失效，所以不复用 B_PE 的盈利限制。两类基准各自命名、计数和留证，不能统一标成同一个不明范围的“行业平均”。

某个财务值缺失，属于估值适用性待定；所需期间已知亏损，属于本默认 PE 比较方案不适用。两者分开呈现，不能都写成数据缺失，也不能让亏损公司的负 PE 因为更小而入选。用户明确只要求一个绝对 PE 条件时，不额外套用上述历史盈利筛选，只检查所用指标本身的有效性。用户只要求历史走势时，也不增加盈利门槛。

每个相对指标单独计算有效样本数和覆盖率：

- 样本数至少 5 个；这是 MVP 的试行下限，不是统计可靠性的通行标准。
- PE 的有效样本数 /（已确认适用数 + 适用性待定数）至少 80%。已知不适用者不进入分母；待定者留在分母，避免通过删掉缺数据公司制造高覆盖。走势覆盖率为有效价格样本数 / U 的总数，不删除历史不足者来抬高比例。
- 有效样本来自同一命名观察组、同一指标口径和本轮数据版本；异常或过期值不得进入统计。
- P50 在当前筛选条件执行前计算。调高营收要求、修改 PE 阈值或结果数量变化，都不重新选择同行、重算本轮基准。

最低样本数和覆盖率属于待验证的产品参数，保留在策略版本中。低于任一门槛时，该比较项无法判断；不能偷偷扩大到整个家电行业，不能改用全市场阈值，也不能让用户猜一个数字补上。

范围规则、盈利门槛和基准明细需要经过业务审核。当前板块清单能取到，并不代表已经完成业务可比性审查或所有指标的取数验收。

### 4.4 不同股票如何处理

| 对象 | 处理 |
|---|---|
| 本观察组中适用的正盈利公司 | 使用上述默认方案，保留业务差异提示 |
| 本组亏损或基期非正的公司 | 说明哪些比较不适用；不自动用 PS 等新指标替换 |
| 银行 | 需要资产质量、资本约束、ROE/PB 等专用框架；首版不生成默认结论 |
| 资源等强周期公司 | 需要判断盈利所处周期，不能把高景气低 PE 直接当作便宜；首版不覆盖 |
| 零部件公司或其他行业 | 不混入当前整机观察组；用户明确要求时说明范围限制 |

这张表用于产品路由，不在首屏做成用户必须回答的分类题。银行、周期、亏损企业的框架说明不代表这些模板已经开发完成。

## 5. 完整用户链路

### 5.1 进入与表达

首屏只展示行业范围、一句示例和一个主按钮。示例为“经营改善、估值别太高、走势相对稳定”。用户可以直接使用，也可以替换成自己的话。按钮为“按这个想法筛选”。

不出现指标下拉框、阈值输入框、风险测评、解析模式选择、报告期必选和强制确认框。范围和默认报告期可见，修改入口不抢主流程。

### 5.2 生成并展示初筛

用户提交后，系统完成解释、适用性检查、基准计算和确定性筛选，直接显示初筛结果。结果顶端保留原话，并用三句短说明概括本次采用的解释。数字必须来自本轮数据，未加载完成时不先展示“找到 N 只”。

需要澄清的内容分级：

| 情形 | 行为 |
|---|---|
| 常规模糊词，已有适用默认方案 | 直接试算，标明默认解释，可随时修改 |
| 明确且支持的参数 | 直接执行，不重复询问 |
| 明确冲突，例如 PE>30 且 PE<15 | 暂停执行，指出冲突；保留原输入，用户可直接修改后重试 |
| 明确要求超出范围，例如银行、扣非增速、OR | 说明未处理项；不能悄悄删掉后展示完整命中名单 |
| 用户想修改但目标不明 | 只问需要区分的目标，用实际条件名称，不让用户选择技术字段 ID |
| 数据或同业基准不足 | 展示哪些项无法核验，保留已验证的事实；不当作偏好问题追问用户 |

目标是常规主链路零追问；异常尽量一次集中处理，但不能为了减少次数丢弃明确要求。仅可推导的默认假设不要求逐项确认；改掉用户明确要求必须得到对应操作。

### 5.3 看结果和理由

结果按股票代码排列，在当前分类下展示完整名单，不排序推荐。每张卡包含：

1. 公司简称、全代码和本轮状态。
2. 本次实际采用的逐项指标、数值和判断；点击依据可见完整比较标准与原因。
3. 一个与本次判断最相关的限制；个股限制必须有证据，通用未核验项单独标明。
4. “查看依据”和“加入对比”。

首屏必须保留原始意图、采用的解释、实际阈值、报告期或价格窗口、数据状态及来源简称。每项目标有一句常显的白话用途，不能把“为什么看它”仅藏在问号或帮助页：经营看收入和股东利润是否一起增加；估值比较每元盈利对应的价格；走势同时看起伏和高点后的回落。具体选值依据、公式、原始字段、请求标识、完整同行名单和参数编辑放在同一个详情面板，避免多层帮助页。

通过“全部”与各状态页签查看完整观察组，明确区分：已知不符合、数据待核验、本默认方案不适用。首版没有单独的名称搜索框。不适用是额外的适用性状态，不混入数据缺失。

对适用股票保留原有三态：所有条件通过则符合；存在已知失败则不符合，即使其他项缺失也保留其缺失原因；没有失败但存在未知则待核验。全观察组满足：符合数 + 不符合数 + 待核验数 + 不适用数 = U 的股票数。池外股票单独说明不在本轮范围。

### 5.4 修改条件

结果页提供“调整要求”。优先显示用户能判断的具体改法：

- “估值放宽一点”：只把默认估值分位由 P50 改为 P75，经营和走势不变。
- “少些起伏和回落”：只把波动率和回撤分位从 P50 改为 P25，其他不变。
- “只改利润要求”等明确自然语言：转换为有限修改，保留未提及部分。

这些按钮不是首屏要求用户先选的档位。点开调整时，先展示本轮数据上的实际变化，例如原数量、新数量、新增或移出的股票和变化原因，用户点击“应用”后生效；保留“一步撤销”。如果数量没有变化，如实显示，不能暗中继续放宽。

快捷操作仅用于单条、方向明确且来自默认分位的上限条件，且实际变化必须符合“放宽”或“收紧”的含义。绝对阈值、相反方向或同字段多条区间不提供该快捷操作，仍可在条件详情编辑。没有可靠基准也不提供快捷操作。

同一轮修改固定数据快照、观察组和基准。刷新数据或切换报告期会建立新运行，不能将新行情变化归因于参数调整。零结果时保留零结果，按同样方式预览单项调整；不默认挑一条放宽。

### 5.5 比较与保存

最多比较三只股票。比较页直接展示各自更突出的事实和未通过项，不给综合推荐分。没有用户明确指定的比较标准时，不替用户选出“最好的一只”。

点击“保存这次筛选”即可完成，以原始想法和时间标识记录，首版不提供重命名。保存原话、系统默认解释、用户明确修改、数据与基准版本，以及实际结果。恢复时标为历史结果，不悄悄更新。默认方案未被逐项确认，不在保存记录中伪造“用户已确认全部参数”。

Demo 继续采用本浏览器保存，不声称同步至同花顺自选或云端。没有新增自动监控、回测、下单或营销触达。

## 6. 技术职责与可解释数据

AI：识别用户目标、保留明确要求、提出实质歧义和局部修改意图。数值冲突最终由确定性程序检验。AI 不自由生成默认阈值，不选同行，不计算分位，不输出入选名单。

版本化策略规则：决定某个业务场景可用哪些指标、采用何种默认解释、是否需要澄清、缺少什么数据。每次计划记录 `knowledgeVersion`，运行记录 version=5；条件保存适用范围与选择理由。

数据及基准服务：获取名单、财报、估值、价格和日历；核对口径与时点；生成观察组、样本覆盖和分位证据。不同数据源分类不混用。

确定性引擎：执行逐项条件及包含适用性在内的四类总状态，生成依据、排除原因及修改差异。原值比较，不按四舍五入值判定。

界面：先给可理解的结果与理由；按需展示参数和原始证据。金融数值、状态、数量和修改影响由程序填充；解释文案使用经审核的模板。

每个条件记录来源为“用户明确 / 产品默认 / 用户修改”；每个相对阈值保留样本列表、排除与缺失原因、分位算法、原始值、来源、获取时间和数据版本。计算失败不输出正常数字。技术契约详见配套设计，不把实现字段名塞入用户界面。

## 7. 范围和发布门槛

本版范围变更：不再以完整上证 50 跨行业筛选作为默认体验；先完成一个明确行业观察组。上证 50 是旧版演示选择，不是题目要求。原有绝对指标筛选能力可复用，但不作为新版默认交互。

必须完成：自然语言入口、默认解释、可执行条件、实质冲突、自然语言与参数修改、真实数据结果、入选与排除依据、时点与缺失状态、变化预览、比较和免命名保存。

首版不做：全行业模板、个人风险画像、盈利预测、合理价格模型、综合打分、交易建议、回测、监控及交易。

实际取数验证：两份名单的完整成分与集合差、全组财报与价格路径、分位样本与覆盖率已实测。2026-10-15本轮观察组11只，9只满足默认PE盈利门槛，10只价格窗口完整；这些只是该次快照结果，不能硬编码为长期保证。业务可比性未逐家核查，作为明确边界保留。

旧版73项测试作为回归基线保留；当前合计101项通过，新增默认基准、适用性、多意图、修改与恢复等验证。另有真实模型和浏览器记录，详见测试报告。本项目经过多轮研究与修订，不宣称从零在两小时内完成。

## 8. 验收与用户验证

| 检查 | 预期 |
|---|---|
| 在支持场景输入示例句 | 不填任何数值、不勾确认、不先选档位，即可看到真实初筛和默认解释 |
| 输入“PE≤20” | 保留 20 和包含边界；不追加未提及的目标 |
| 打开任一默认条件 | 能看到为何采用、实际阈值、阈值来源、适用范围及修改入口 |
| 查看任一入选与未入选股票 | 能回到本轮事实与判定；未知与已知失败分开 |
| 同业样本不足或覆盖不足 | 不使用全市场替补，不要求用户随便输入 PE，不生成正常估值结论 |
| 同行数据异常、接口失败或模型失败 | 显示对应状态；保留原输入及有效结果；没有伪造成功 |
| 仅放宽估值 | 固定快照和基准，经营与走势不变；通过集合不能减少 |
| 模型尝试顺便改变范围、报告期或其他条件 | 校验拒绝或明确预览，不静默执行 |
| 默认低波动公司持续下跌 | 回撤也必须核验；不出现“不会亏”“走势安全”等结论 |
| 保存与恢复 | 无需命名即可保存；默认假设来源保留，历史状态可见 |
| 银行、亏损成长股、明天必涨等请求 | 不套白电默认方案、不输出买卖建议或收益承诺 |
| 公开匿名访问与源码交付 | 主链路实操通过；PRD、测试和 AI 记录与实现版本一致 |

拟招募 5 位符合目标画像的用户，分别使用旧版和新版，平衡使用顺序，不由 AI 扮演真实受试者。观察其完成任务、解释入选原因、放宽一项条件并保存。记录首次结果耗时、强制输入数、求助次数、错误操作和理解情况；不把点击减少直接当作理解改善。

初步放行目标：至少 4 人无需讲解完成常规链路，并能说清“为何采用这个标准”和“放宽后变化什么”；发现任何“入选就该买”“中位数就是合理价”的误解，都回到解释设计修订。5 人结果只能用于发现可用性问题，不用于推算全量用户提升比例。

自动化验收与真人验证均未在本轮完成。关键设计假设及反例见研究与审查记录。


## 本轮追加：多问法与策略映射

知识库覆盖19类输入目标，其中11类在当前数据能力内执行。首屏提供六个不同目标组合，均为研究后的构造例子，不冒充真实客户日志。分红、现金流、质量、多期加速、业绩超预期、盘中量价及其他行业专用估值只解释缺口，不擅自替换。

观察组未完成逐家公司商业模式可比性审核，因此仅使用“本组参考线”，公开集合差规则和盈利适用门槛，不给公允估值结论。明确的数字表达可以直接确定性解析，并注明未调用模型；模糊目标调用模型识别，不必为简单比较增加模型问答。
